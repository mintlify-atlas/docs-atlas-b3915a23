---
title: "neonctl branches: manage branches via CLI"
description: "List, create, rename, reset, restore, delete, and inspect Neon branches from the terminal using the neonctl branches command and its subcommands."
---

The `neonctl branches` command lets you manage branches in a Neon project from the terminal. Branches are isolated copies of your database that you can create, modify, and delete without affecting your production data. You can also add compute endpoints to a branch, compare schemas across branches, reset a branch to its parent, and restore a branch to any point in its history.

<Note>
  Before running `branches` commands, [install the Neon CLI](/reference/neon-cli) and authenticate using `neon auth` or by setting a `NEON_API_KEY` environment variable. Most subcommands require `--project-id` only when your account has more than one project.
</Note>

## Usage

```bash
neon branches <subcommand> [options]
```

| Subcommand | Description |
|---|---|
| [`list`](#list) | List branches |
| [`create`](#create) | Create a branch |
| [`reset`](#reset) | Reset a branch to its parent |
| [`restore`](#restore) | Restore a branch to a point in time |
| [`rename`](#rename) | Rename a branch |
| [`schema-diff`](#schema-diff) | Compare schemas between branches |
| [`set-default`](#set-default) | Set a branch as the default |
| [`set-expiration`](#set-expiration) | Set automatic expiration for a branch |
| [`add-compute`](#add-compute) | Add a compute endpoint to a branch |
| [`delete`](#delete) | Delete a branch |
| [`get`](#get) | Get details about a branch |

## list

### Usage

```bash
neon branches list [options]
```

### Options

## create

Creates a new branch in a Neon project. By default, the branch is created from the project's default branch and receives a read-write compute endpoint.

### Usage

```bash
neon branches create [options]
```

### Options

| Option | Description | Type |
|---|---|---|
| `--name` | Branch name. Defaults to the branch ID if not specified. Max 256 characters | string |
| `--parent` | Parent branch name, ID, timestamp, or LSN. Defaults to the project's default branch | string |
| `--compute` | Create the branch with a compute. Use `--no-compute` to create without one. Default: `true` | boolean |
| `--type` | Compute type: `read_write` (default) or `read_only` (read replica) | string |
| `--cu` | Compute size. Fixed (e.g., `"2"`) or autoscaling range (e.g., `"0.5-3"`) | string |
| `--suspend-timeout` | Inactivity seconds before compute suspends. `0` = global default, `-1` = never suspend. Default: `300` | number |
| `--schema-only` | Create a schema-only branch (no data copied from parent) | boolean |
| `--expires-at` | Auto-delete timestamp in RFC 3339 format | string |
| `--psql` | Connect to the new branch via `psql` after creation | boolean |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

### Examples

Create a branch with an auto-generated name:

```bash
neon branches create
┌─────────────────────────┬─────────────────────────┬─────────┬──────────────────────┬──────────────────────┐
│ Id                      │ Name                    │ Default │ Created At           │ Updated At           │
├─────────────────────────┼─────────────────────────┼─────────┼──────────────────────┼──────────────────────┤
│ br-mute-sunset-67218628 │ br-mute-sunset-67218628 │ false   │ 2023-08-03T20:07:27Z │ 2023-08-03T20:07:27Z │
└─────────────────────────┴─────────────────────────┴─────────┴──────────────────────┴──────────────────────┘
endpoints
┌───────────────────────────┬──────────────────────┐
│ Id                        │ Created At           │
├───────────────────────────┼──────────────────────┤
│ ep-floral-violet-94096438 │ 2023-08-03T20:07:27Z │
└───────────────────────────┴──────────────────────┘
connection_uris
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ Connection Uri                                                                           │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ postgresql://[user]:[password]@[neon_hostname]/[dbname]                                  │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

<Note>
  If the parent branch has more than one role or database, `branches create` does not output a connection URI. Use `neon connection-string` with the `--role-name` and `--database-name` options to retrieve it.
</Note>

Create a branch with a user-defined name:

```bash
neon branches create --name feature/user-auth
```

Create a branch from a specific parent branch:

```bash
neon branches create --name feature/payment-api --parent development
```

Create a branch from a point in time (instant restore branch):

```bash
neon branches create --name data_recovery --parent 2023-07-11T10:00:00Z
```

Timestamps must be in RFC 3339 format. See [Instant restore](https://neon.tech/docs/guides/branch-restore) for details.

Create a read replica branch:

```bash
neon branches create --name my_read_replica_branch --type read_only
```

Create a branch with autoscaling enabled:

```bash
neon branches create --name mybranch --cu 0.5-3
```

Create a schema-only branch (no data is copied from the parent):

```bash
neon branches create --schema-only
```

## reset

Resets a branch to the latest data from its parent. This is equivalent to a `git reset --hard` against the parent branch.

### Usage

```bash
neon branches reset <id|name> --parent [options]
```

The `--parent` flag is required. It specifies that the reset source is the branch's parent.

### Options

| Option | Description | Type |
|---|---|---|
| `--parent` | Reset to the parent branch (required) | boolean |
| `--preserve-under-name` | Name to save the current branch state before resetting | string |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

### Example

```bash
neon branches reset development --parent
┌──────────────────────┬─────────────┬─────────┬──────────────────────┬──────────────────────┐
│ Id                   │ Name        │ Default │ Created At           │ Last Reset At        │
├──────────────────────┼─────────────┼─────────┼──────────────────────┼──────────────────────┤
│ br-aged-sun-a5qowy01 │ development │ false   │ 2024-05-07T09:31:59Z │ 2024-05-07T09:36:32Z │
└──────────────────────┴─────────────┴─────────┴──────────────────────┴──────────────────────┘
```

## restore

Restores a branch to a specified point in its own or another branch's history.

### Usage

```bash
neon branches restore <target-id|name> <source>[@(timestamp|lsn)] [options]
```

`<source>` accepts:
- `^self` — restore to an earlier point in the branch's own history (requires a timestamp or LSN and `--preserve-under-name`)
- `^parent` — restore to the parent branch (defaults to head; append `@timestamp` or `@lsn` for a specific point)
- A branch ID or name — restore from another branch (defaults to head; append `@timestamp` or `@lsn` for a specific point)

### Options

| Option | Description | Type |
|---|---|---|
| `--preserve-under-name` | Name for the backup branch created before restoring to `^self` | string |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

### Examples

Restore `main` to an earlier point in its own history, saving the current state as a backup:

```bash
neon branches restore main ^self@2024-05-06T10:00:00.000Z --preserve-under-name main_restore_backup_2024-05-06
INFO: Restoring branch br-purple-dust-a5hok5mk to the branch br-purple-dust-a5hok5mk timestamp 2024-05-06T10:00:00.000Z
Restored branch
┌─────────────────────────┬──────┬──────────────────────┐
│ Id                      │ Name │ Last Reset At        │
├─────────────────────────┼──────┼──────────────────────┤
│ br-purple-dust-a5hok5mk │ main │ 2024-05-07T09:45:21Z │
└─────────────────────────┴──────┴──────────────────────┘
Backup branch
┌─────────────────────────┬────────────────────────────────┐
│ Id                      │ Name                           │
├─────────────────────────┼────────────────────────────────┤
│ br-flat-forest-a5z016gm │ main_restore_backup_2024-05-06 │
└─────────────────────────┴────────────────────────────────┘
```

Restore `feature/user-auth` to the latest data from `main`:

└────────────────────────────┴───────────────────┴──────────────────────┘

Restore `feature/user-auth` to a specific point in its parent's history:

## schema-diff

Compares the schemas of two branches, or compares a branch against an earlier point in its own or another branch's history. The output is a unified diff showing SQL differences.

### Usage

```bash
neon branches schema-diff [base-branch] [compare-source[@(timestamp|lsn)]] [options]
```

`[base-branch]` is optional. If omitted, the command uses the branch in your context file, or the project's default branch.

`[compare-source]` accepts:
- `^self` — compare to an earlier point in the branch's own history (requires a timestamp or LSN)
- `^parent` — compare to the head of the parent branch (optionally `@timestamp` or `@lsn`)
- A branch ID or name — compare to another branch (optionally `@timestamp` or `@lsn`)

### Options

| Option | Description | Type |
|---|---|---|
| `--database`, `--db` | Database name to compare | string |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

<Tip>
  Use `--no-color` when running `schema-diff` in CI/CD pipelines to get plain-text diff output without ANSI color codes.
</Tip>

### Examples

Compare `production` to the head of `development`:

```bash
neon branches schema-diff production development
```

Compare `feature/user-auth` against an earlier point in its own history using an LSN:

```bash
neon branches schema-diff feature/user-auth ^self@0/123456
```

Compare `feature/user-auth` to the head of its parent:

```bash
neon branches schema-diff feature/user-auth ^parent
```

Compare `production` to a specific timestamp in another branch's history:

```bash
neon branches schema-diff production feature/payment-api@2024-06-01T00:00:00.000Z
```

## set-expiration

Sets or updates the automatic expiration timestamp for a branch. When the expiration time is reached, the branch and all its compute endpoints are permanently deleted.

### Usage

```bash
neon branches set-expiration <id|name> --expires-at <timestamp> [options]
```

`--expires-at` accepts a timestamp in RFC 3339 format (e.g., `2025-08-15T18:00:00Z`). Omit the flag to remove an existing expiration.

### Options

| Option | Description | Type |
|---|---|---|
| `--expires-at` | Expiration timestamp in RFC 3339 format | string |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

### Examples

Set a branch to expire on a specific date:

```bash
neon branches set-expiration mybranch --expires-at 2025-08-15T18:00:00Z
```

Remove expiration from a branch:

```bash
neon branches set-expiration mybranch
```

## add-compute

Adds a compute endpoint to an existing branch. A branch can have one primary read-write compute and multiple read replica (read-only) computes.

### Usage

```bash
neon branches add-compute <id|name> [options]
```

### Options

| Option | Description | Type |
|---|---|---|
| `--type` | Compute type: `read_only` (default) or `read_write` | string |
| `--cu` | Compute size. Fixed (e.g., `"2"`) or autoscaling range (e.g., `"0.5-3"`) | string |
| `--project-id` | Project ID | string |
| `--context-file` | Context file path and file name | string |

Along with these options, all [global options](/reference/neon-cli#global-options) are supported.

### Examples

Add a read replica to a branch:

```bash
neon branches add-compute mybranch --type read_only
┌─────────────────────┬──────────────────────────────────────────────────┐
│ Id                  │ Host                                             │
├─────────────────────┼──────────────────────────────────────────────────┤
│ ep-rough-lab-865061 │ ep-rough-lab-865061.ap-southeast-1.aws.neon.tech │
└─────────────────────┴──────────────────────────────────────────────────┘
```

Add a compute with a fixed size of 2 Compute Units:

```bash
neon branches add-compute main --cu 2
```

Add a compute with an autoscaling range:

```bash
neon branches add-compute main --cu 0.5-3
```
