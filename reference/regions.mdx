Neon supports deploying projects across multiple AWS and Azure regions. Choosing a region that is geographically close to your application servers reduces round-trip latency and can improve query response times. This page lists all available regions, explains how to select one, and describes your options if you need to move data to a different region later.

<Note>
A project's region is fixed at creation time and cannot be changed. To run your database in a different region, you must create a new project there and migrate your data.
</Note>

## Azure regions

Azure region support is currently undergoing changes. See the Neon Console for up-to-date availability when creating a project.

## Selecting a region

You choose the region when you create a Neon project. All branches and databases in that project are created in the same region.

<Steps>
  <Step title="Open project creation">
    Go to the [Neon Console](https://console.neon.tech) and click **New project**.
  </Step>
  <Step title="Choose a region">
    In the **Region** dropdown, select the region closest to your application server or end users.
  </Step>
  <Step title="Complete project setup">
    Fill in any remaining settings (Postgres version, compute size) and click **Create project**. The region is set permanently at this point.
  </Step>
</Steps>

<Tip>
If you are deploying to a cloud provider like AWS, Vercel, or Render, match the Neon region to the region where your application is hosted. For example, if your API runs in `us-east-1`, use `aws-us-east-1` for your Neon project.
</Tip>

## Region considerations

### Latency

Database query latency increases with physical distance between the database and the application. A compute in the same AWS region as your application server will typically add only single-digit milliseconds of overhead. Cross-region connections can add 50–200 ms or more depending on geography.

### Data residency

Some organizations have legal or compliance requirements that restrict where data can be stored. Choose a region that satisfies your data residency obligations at project creation time. You cannot move data to another region without explicitly migrating it.

### Region availability

Not all Neon features are available in every region at the same time. Feature rollouts generally appear in AWS US East regions first. Check the Neon Changelog for region-specific announcements.

## Moving data to another region

A project's region cannot be changed after creation. If you need your data in a different region, you must create a new project in the target region and migrate your database there.

<Warning>
You are not moving the existing project. You are creating a separate project in a new region and copying data into it. The original project continues to exist until you delete it.
</Warning>

See [Region migration](/import/overview) for step-by-step instructions, including prerequisites and the available migration paths.

## Requesting a new region

If you need a region that is not currently available, you can submit a request. Look for the region request form in the Neon Console, or reach out on the [Neon Discord](https://discord.gg/92vNTzKDGp).
